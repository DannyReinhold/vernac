# Vernac 0.5.4

- **IDE.** IntelliJ Reformat Code supports models, application definitions and module
  manifests. It preserves comments and embedded Java. MVC template names support
  completion and navigation. The project wizard presents its existing templates as
  radio buttons. The minimum IntelliJ build stays at `262.10968.63`.
- **Domain model.** Declare [unique aggregate fields](../../contracts/aggregate-uniqueness.md)
  and [global aggregate ID references](../../contracts/global-id-references.md).
  Ordinary [value objects](../../contracts/value-objects.md#string-representation)
  can supply a custom `toString()` using behavior.
- **Persistence.** [Extend generated JDBC repositories](../../contracts/repository-extensions.md)
  with custom SQL and canonical aggregate loading. [Explicit tenancy](../../contracts/explicit-tenancy.md)
  extends PostgreSQL persistence, module activation and durable event delivery.
- **Access.** Model typed permissions and application roles and
  [declare what usecases require](../../contracts/usecase-authorization.md).
  MVC supports [declarative text downloads](../../contracts/inbound-mvc.md#text-downloads).
- **Platform.** [Spring Boot 4.1.2 and Jackson 3](../../development/spring-boot-4-baseline.md)
  are the integration baseline. Applications and generated Java still target Java 21.
  The standard Spring Boot template and bundled web examples use YAML configuration.

## Upgrade notes

Use matching compiler, plugin and runtime artifacts. Align Spring Boot dependencies,
starters and custom JSON codecs with the new platform baseline. Rebuild both producers
and consumers of Vernac modules against the new metadata format. For persistent
applications, review and apply generated migration candidates where the deployed
schema and the new model differ. Follow the [event-origin migration guidance](../../development/event-origin-schema.md)
for applications that already store events.
