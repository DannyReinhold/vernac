# Vernac 0.5.1 — Debugger compatibility

This maintenance release removes an unnecessary call to the internal IntelliJ
`NodeRendererImpl.setIsApplicableChecker` API. The debugger renderer uses the
platform's existing applicability dispatch to its Vernac view type check.
Source breakpoints, stepping, expressions and Read/Access view inspection retain
their existing behavior. No language, persistence or migration changes are included.

The existing real-JVM view inspection test now also checks asynchronous renderer
applicability for generated views and rejection of primitive values.

## Publish the hotfix

Use a hotfix branch based on the released 0.5.0 commit, not the 0.6.0 development
branch. Run **Vernac Release** with `version=0.5.1` and `dry_run=true`; after it passes,
merge into `main` and run with `version=0.5.1` and `dry_run=false`.
The workflow supplies the version through `-Drevision`; the checked-in default
snapshot version does not determine the published version. Publish the matching
Maven artifacts and plugin together. Check the Marketplace verifier report for the
actual ZIP, then tag the released commit `v0.5.1` and create its GitHub release.
Do not move `v0.5.0` or replace its artifacts.

Forward-port the fix into `feature/0.6.0`, preserving its `0.6.0-SNAPSHOT` version.
