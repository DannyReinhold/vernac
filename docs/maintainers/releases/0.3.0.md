# Vernac 0.3.0

Release-note draft: use after the corresponding publication steps have completed.
Record the exact release commit, workflow run and actual distribution status when
creating the GitHub Release. This page alone does not announce publication.

## Make an application operation accessible over HTTP

Vernac 0.3.0 adds generated Spring MVC inbound adapters around declared usecases.
Model path/query/header/body inputs, convert wire data into validated domain values,
and map the usecase's declared answer into a transport DTO. Transaction boundaries
remain in the usecase; generated controllers contain transport/ACL work.

The Dispatch showcase uses this for its create/release endpoints. Other Java web
operations remain alongside them, demonstrating incremental adoption.

## A clearer compiler and learning path

Project compilation shares resolution and generation across files/namespaces.
Obsolete experimental compiler paths and per-definition package syntax are removed.
The documentation now consistently targets 0.3.0, explains common failure situations,
and connects model, persistence, migrations, events and integration. The AI reference
includes a compiled inbound HTTP example with an explicit usecase Result.

The existing domain, optimistic aggregate persistence, Flyway candidates, durable
events and outbound ports/ACL remain available. Schema history is not automatically
rewritten; review migration candidates and model changes deliberately.

## Distribution and requirements

- Maven artifacts: org.vernac coordinates at **0.3.0**, after Central publication.
- IntelliJ: org.vernac plugin **0.3.0**, after Marketplace approval; the verified ZIP
  and provenance manifest are retained with its GitHub release.
- Repository/plugin builds: JDK **25**; release automation pins Maven **3.9.16**.
- Generated application code: Java **21**. PostgreSQL examples use PostgreSQL **17**.
- IDE compatibility: consult the packaged plugin.xml and Marketplace listing.

Use matching compiler/runtime/plugin versions. Source examples default to
0.3.0-SNAPSHOT; select `-Dvernac.version=0.3.0` for standalone released consumers.
Regenerate Java after updating the compiler and adjust callers to the current API.

## Deliberate limits

- Inbound HTTP is synchronous Spring MVC; it adds no security, automatic retries,
  idempotency, OpenAPI or asynchronous transport.
- A response failure may occur after a command has committed. An HTTP error alone
  is not a safe reason to repeat the command.
- Failed domain modifications and database rollbacks do not restore Java objects.
- External effects require their own retry/idempotency policy.
- Migration candidates require developer review, testing and approval; structural
  replay on empty databases is not a production-data guarantee.
- Generic versioned subdomains, declarative SaaS authorization and deeper IDE
  refactoring/debugger integration remain planned.
